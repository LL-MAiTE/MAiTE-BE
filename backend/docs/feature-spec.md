# AI 비동기 협업 대리 진행 서비스 — 최종 기능 명세서

## 타겟 정의

> Claude, Notion, Git/GitHub 등을 활용해 프로젝트 결정 사항과 업무 맥락을 문서(md, 위키, 회의록 등)로 구조화해 관리하는 IT/개발 조직의 실무자와 팀 리더. 해외 고객·개발팀·협력사와 반복적으로 다국어 음성 미팅을 진행하며, 이미 AI 도구를 업무에 자연스럽게 통합해 쓰고 있어 AI에게 맥락과 진행을 위임하는 데 거부감이 적은 제품, 개발, 영업, 운영 담당자를 대상으로 한다.

---

## 용어 정리 (계층 구조)

| 용어 | 설명 |
|------|------|
| **프로젝트** | 문서를 계속 쌓아두는 단위 (책장) |
| **회의** | 이름 + 목적을 입력하고, 프로젝트에 쌓인 문서 중 관련 파일을 선택해서 만드는 단위. 이전 버전 문서에서 "안건"이라 부르던 것과 동일한 실체이며, 이하 "회의"로 용어를 통일한다. |
| **안건(항목)** | 회의 하나에 속한 개별 예상 질문-답변 단위. AI가 생성하거나 사용자가 직접 추가한다. 이전 버전 문서에서 "항목"이라 부르던 것과 동일. |

## 기능 명세 (중요도 순)

### 1. 프로젝트 문서 연동 및 맥락 수집 🔴 최상

**목적**
답변 작성자가 사전 입장을 처음부터 직접 입력하지 않아도, 이미 존재하는 프로젝트 문서에서 AI가 맥락을 파악할 수 있게 한다.

**입력받을 것**

- **프로젝트 핵심 맥락 md** (선택 업로드) — 프로젝트 개요, 목적, 팀 구성 등 "이 프로젝트가 뭔지"를 담은 문서. AI가 프로젝트의 큰 틀을 잡는 데 우선적으로 참고
- md 파일 업로드 또는 폴더 연결 (회의록, 의사결정 로그 등 — 책장처럼 계속 누적)
- Notion/Git 연동 시 접근 토큰 (해커톤 MVP는 Internal Integration/Personal Access Token 방식 — 심사 불필요, 정식 출시 시 OAuth Public Integration 전환 필요)

**출력받을 것**

> 예시: "docs/decisions/2026-08-pricing.md 등 12개 문서를 연동했습니다. 최근 수정 파일: 가격 정책 변경(3건), API 마감일(2건)"

**비즈니스 규칙**

- 문서는 프로젝트 단위로 계속 누적 업로드/연동. 회의마다 처음부터 자료를 다시 올리지 않고, 이미 쌓인 문서들 중에서 고른다.
- 핵심 맥락 md는 하나(또는 소수)로 지정 가능하며, 회의 생성 시 파일 선택 목록에 항상 우선 노출되고 AI 생성 시에도 항상 참고된다.

---

### 2. 회의 생성 및 AI 안건 초안 생성 🔴 최상

**목적**
답변 작성자가 회의 이름·목적을 입력하고 관련 파일을 선택하면, 그 파일들을 근거로 AI가 예상 안건(질문)과 답변 초안을 먼저 작성해 답변 작성자는 확인·수정만 하면 되게 한다.

**입력받을 것**

- 회의 이름, 목적
- 상대방 정보 (국가, 언어, 소속)
- **프로젝트에 쌓인 문서 목록에서 관련 파일 선택** (핵심 맥락 md는 기본 포함 상태로 노출, 나머지는 사용자가 골라서 체크) — 이 선택이 회의 생성의 필수 단계

> 사용자가 미리 "얼마나 상세히 준비할지" 레벨을 고르는 단계는 없음. 대신 어떤 문서를 근거로 쓸지는 사용자가 직접 선택하고, 그 안에서 AI가 안건별로 필요한 필드만 채워서 제시하면 사용자는 그걸 보고 판단.

**출력받을 것**

> 예시: "예상 안건: 'API 마감일을 앞당길 수 있나요?' → 초안: 선호안 '8/25 유지', 양보범위 '최대 8/28까지 가능' (근거: schedule-agreement.md)"

- 선택한 파일 범위 안에서 생성된 예상 안건(질문)-답변 쌍 리스트
- 각 안건이 근거로 쓴 문서 표시
- 신뢰도 표시 (문서 근거 명확 vs 추정)
- 생성 후에도 **선택 파일 목록에 문서를 추가/제외**할 수 있으며, 조정하면 AI가 해당 범위로 안건을 다시 생성

**비즈니스 규칙**

- AI는 안건(질문)마다 관련 있는 필드만 채운다.
  - 예: 일정 관련 질문 → 선호안 + 양보범위 위주로 채움
  - 예: 계약 관련 질문 → 양보불가사항 포함해서 채움
- 파일을 하나도 선택하지 않고 회의를 만들 수는 없다 (최소 1개, 핵심 맥락 md만 선택해도 무방).
- 해커톤 MVP는 선택된 파일들을 긴 컨텍스트에 직접 투입하는 방식으로 시작, 문서량이 많아지면 RAG(임베딩+벡터검색) 방식으로 전환 가능.

### 3. 안건과 권한 범위 승인 🔴 높음

**목적**
답변 작성자가 AI 초안을 검토·승인하거나, 직접 새 안건을 추가해 승인된 내용만 AI 대리 진행에 사용되도록 확정한다.

**입력받을 것**

- AI 생성 초안에 대한 승인/수정/반려 선택
- **사용자가 직접 추가하는 새 안건(질문-답변 쌍)** (AI가 예상하지 못한 질문 보완용) — 이때도 답변, 선호안, 양보범위, 양보불가사항, 우선순위, 일정제약 중 관련 있는 필드만 선택적으로 입력하면 됨

**출력받을 것**

> 예시: "12개 안건 중 9개 승인, 2개 수정 후 승인, 1개 보류 처리됨. 사용자 직접 추가 안건 2건 포함"

**비즈니스 규칙 — 버전 관리**

- 안건은 주제(topic) 단위로 독립적인 버전을 가짐. 회의 준비 시점(체크포인트)마다:
  - 안 건드린 안건 → 새 버전 생성 없이 마지막 버전을 그대로 유지(carry-over)
  - 수정된 안건 → 새 버전 생성 (v1→v2 등)
  - 삭제된 안건 → 버전 생성 없이 "삭제됨" 상태로 전환, 이후 매칭 대상에서 제외
  - 신규 추가 안건(AI 초안이든 사용자 직접 추가든) → v1부터 시작
- AI 대리 진행(기능 6)은 항상 가장 최근 체크포인트의 스냅샷(주제별 최신 활성 버전 모음)만 참조.
- 승인되지 않은 내용은 AI 대리 진행에 사용할 수 없다.

### 4. 실시간 음성 인식 및 화자 분리 🔴 높음

**목적**
음성 미팅 중 발화를 실시간으로 텍스트화하고 화자별로 구분해, 이후 의도 매칭·통역·회의록 검토의 기초 데이터를 만든다.

**입력받을 것**

- 실시간 음성 스트림 (참여자별 마이크 입력)
- 채널 설정 (전사 언어 최대 2개까지 동시 지정 — Agora 제약)

**출력받을 것**

> 예시: "[화자A, 14:02:11] 'API 마감일 3일만 당길 수 있나요?' / [화자B(AI), 14:02:15] '8/28까지는 가능합니다'"

- 화자별 라벨이 붙은 실시간 전사 텍스트
- `.vtt` 형식 내보내기 지원

**제약사항 (Agora 스펙 기준)**

- 동시 화자 구분은 최대 3명까지
- 채널당 동시 전사 언어는 최대 2개

---

### 5. AI 대리 진행 고지 🔴 높음

**목적**
음성 미팅 시작 시 AI가 대리 진행 중임과 승인 범위, 보류 원칙을 모든 참여자에게 명확히 알려 신뢰를 확보한다.

**입력받을 것**

- 승인된 안건이 연결된 회의
- 미팅 시작 트리거

**출력받을 것**

> 예시(음성 고지): "저는 재현님을 대신해 사전 승인된 범위 안에서 진행합니다. 범위를 벗어나는 사안은 보류 후 전달됩니다."

---

### 6. 승인 답변 통역 전달 (+ 숫자/단위 확인) 🔴 높음

**목적**
상대방의 질문에 대해 핵심 의도가 일치하는 사전 승인 안건만 찾아 통역·전달한다. 숫자/단위가 포함된 경우 오인식 리스크를 줄이기 위해 별도 확인 절차를 거친다.

**입력받을 것**

- 실시간 전사 텍스트 (기능 4의 결과물)
- 승인된 안건 데이터베이스 (기능 3의 최신 스냅샷)
- 번역 대상 언어 (최대 4개 소스 → 10개 타겟, 30개+ 언어 지원 — Agora 스펙 기준)

**출력받을 것**

> 예시: "[질문] '계약 기간도 늘려야 하나요?' → [전달] '8/28까지는 가능, 계약기간 연장은 보류로 기록합니다.'"

- 원문·번역문 병기 자막
- 참조한 승인 안건

**비즈니스 규칙 — 숫자/단위 확인**

- 통역 답변에 숫자·금액·일정·수량 등 핵심 수치가 포함된 경우, 전달과 동시에 상대방(질문 참여자) 화면에 확인 팝업 노출: `"8/28이 맞습니까? [O] [X]"`
  - O 응답 → 전달 확정
  - X 응답 또는 10초 내 미응답 → **자동 보류** (자동 승인 아님) → 회의 종료 후 답변 작성자에게 전달
- 매 숫자마다가 아니라, 계약·가격·일정처럼 중요도 높은 수치에만 적용해 미팅 흐름 방해 최소화

### 7. 승인 범위 내 대안 조율 🟠 중간

**목적**
승인된 선호안과 양보 범위 안에서만 대안을 비교하고 다음 행동·일정을 조율한다.

**입력받을 것**

- 질문 참여자가 제안한 대안/일정
- 관련 안건의 승인된 선호안·양보범위

**출력받을 것**

> 예시: "제안된 납기(9/1)는 승인된 범위(8/25~9/5) 안에 있어 조율 가능"

---

### 8. 보류 항목 비동기 후속 처리 🟠 중간

**목적**
승인 범위 밖 요청이나 숫자확인 실패 항목을 회의 중 보류로 기록하고, 종료 후 답변 작성자가 답하면 상대방에게 비동기로 전달한다. 원래 목적(실시간 핑퐁 제거)을 지키기 위해, 이 후속 처리도 무한정 반복되지 않도록 설계한다.

**입력받을 것**

- 회의 중 기록된 보류 사유(핵심의도 불일치, 숫자확인 미응답/거부 등)와 관련 대화 구간
- 답변 작성자가 작성한 후속 답변

**출력받을 것**

> 예시: "보류 항목 2건: (1) 계약기간 연장 여부 [음성구간 재생] (2) 숫자확인 미응답 항목 [음성구간 재생]"
>
> 답변 작성자가 답한 뒤: "상대방에게 전달됨. 24~48시간 내 별도 이의 없으면 자동으로 확정 처리됩니다."

**비즈니스 규칙 — 핑퐁 방지 설계**

- 답변 작성자가 보류 항목에 답하면, 그 답변은 상대방(질문 참여자)에게 비동기로 전달된다. **기본은 "1회 답변으로 종결"** — 상대방의 "만족했습니다" 같은 확인을 별도로 요구하지 않는다.
- 상대방이 그 답변에 만족하지 못하면 **능동적으로 재오픈**할 수 있다. 재오픈은 **같은 항목당 최대 2회**로 제한한다.
- 재오픈 상한(2회)에 도달하면, 시스템은 "이 사안은 비동기로는 해결이 어렵습니다. 실시간 미팅을 다시 잡아주세요"라고 양측에 안내하고 해당 항목은 "실시간 조율 필요"로 종결한다.
- 답변 작성자의 후속 답변 전달 후 **24~48시간 안에 상대방이 재오픈하지 않으면 자동으로 확정 처리**된다.
  - 미응답 = 확정 (숫자확인의 "미응답 = 자동 보류"와 반대 방향 — 숫자확인은 확정성 검증이라 안전 쪽으로 설계, 여기는 회의를 무한정 열어두지 않기 위한 종료 로직)

### 8-1. 사후 재보류 (승인·반려 뒤집기) 🟡 낮음

**목적**
회의 중 AI가 실시간으로 내린 판단(승인/전달)이 사후검토에서 보니 잘못됐을 수 있다. 답변 작성자가 이를 발견하면 다시 보류 상태로 되돌릴 수 있게 한다.

**입력받을 것**

- 사후검토 화면에서 답변 작성자가 "재보류" 선택
- 재보류 사유

**출력받을 것**

> 예시: "'8/28까지 가능'으로 전달됐던 안건을 재보류로 전환했습니다. 사유: 승인 범위를 벗어난 매칭으로 판단됨"

- 재보류된 항목은 기능 8의 후속 처리 흐름(답변 → 비동기 전달 → 24~48시간 후 자동확정 또는 재오픈)을 동일하게 따른다.

**비즈니스 규칙**

- 재보류도 재오픈 횟수에 포함되어 같은 상한(최대 2회)이 적용된다.

> **미팅 종료 규칙**: 미팅은 실시간 음성 세션 하나로 끝나지 않고, 보류 항목이 있으면 "후속답변대기" 상태로 비동기 이어짐. 모든 보류 항목이 (a) 확정(즉시 만족 또는 24~48시간 타임아웃) 되거나 (b) 재오픈 상한 도달로 "실시간 조율 필요"로 종결되면, 미팅은 자동으로 "종료" 상태가 된다. 양측이 별도로 "종료" 버튼을 누르는 절차는 두지 않는다 — 각 항목이 종결되는 순간 자동 반영되는 구조로, "종료 확인"을 위해 또 왔다갔다 하는 핑퐁을 만들지 않기 위함.

---

### 9. 대화별 회의 결과 검토 🟡 낮음

**목적**
답변 작성자가 화자별 대화 전문과 음성 구간을 보며 AI 전달 내용과 상대 반응을 검토·승인·수정·철회한다.

**입력받을 것**

- 종료된 미팅의 화자별 대화 전문, 음성 기록
- 항목별 승인/수정/철회/**재보류** 선택 (재보류는 기능 8-1로 연결)

**출력받을 것**

> 예시: "[대화 #14] AI: '8/28까지 가능' → 상대 반응: '좋습니다' → [승인]"

---

### 10. 필수 검토 항목 관리 🟡 낮음

**목적**
상대방이 지정한 중요 합의 항목을 답변 작성자가 놓치지 않도록 조건부 합의로 관리한다.

**입력받을 것**

- 질문 참여자의 필수 검토 지정 트리거
- 답변 작성자의 확인 결과

**출력받을 것**

> 예시: "[조건부 합의] 계약기간 연장 — 확인 전까지 확정 아님 → 확인 후 '확정'으로 전환"

### 11. 알림 🟠 중간

**목적**
비동기 후속 처리(기능 8) 흐름에서 답변 작성자와 질문 참여자가 각자 해야 할 액션이 생겼을 때 인지할 수 있게 한다.

**알림이 발생하는 시점**

| 이벤트 | 수신자 |
|--------|--------|
| 보류 항목이 새로 생김 (회의 중 발생) | 답변 작성자 |
| 답변 작성자의 후속 답변이 전달됨 | 질문 참여자 |
| 질문 참여자가 재오픈 요청 | 답변 작성자 |
| 24~48시간 타임아웃으로 자동 확정됨 | 양쪽 |
| 재오픈 상한 도달 → 실시간조율필요 | 양쪽 |
| 모든 보류 항목 종결 → 미팅 자동 종료 | 양쪽 |
