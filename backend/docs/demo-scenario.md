# 발표/데모용 시나리오

등장인물: 한국 PM **재현** (답변 작성자), 미국 개발팀 리드 **사라** (질문 참여자).

이 스토리 하나가 기능 1~10을 전부 관통합니다. 발표 스크립트로 그대로 활용 가능합니다.

---

## 몇 주 전, 재현 — 프로젝트 만들기

재현은 이 프로젝트를 처음 만들 때, 프로젝트 개요를 담은 md 파일 하나(`project-overview.md` — 팀 구성, 도메인, 핵심 목표 요약)를 가장 먼저 올려서 "이 프로젝트가 뭔지" AI가 큰 틀을 잡게 해뒀습니다. 이 문서는 **핵심 맥락 문서**로 지정되어, 이후 어떤 회의를 만들든 파일 선택 목록에 항상 우선 노출됩니다. *(기능 1 — 핵심 맥락 md)*

이후로는 회의록, 결정사항 같은 문서들을 책장에 책 꽂듯 계속 업로드/연동해뒀습니다. Notion에도 이미 관련 문서가 쌓여있어 프로젝트 생성 시점에 연동해둔 상태입니다. *(기능 1 — 문서 연동은 프로젝트 단위로 계속 누적)*

---

## 목요일 저녁 6시, 재현 — 회의 만들기

내일 새벽에 사라 팀과 "API 마감일" 관련 미팅이 잡혀있습니다. 재현은 새벽 3시까지 깨어있고 싶지 않아 서비스에 들어가 회의를 하나 만듭니다.

- 회의 이름: "API 마감일 협의", 목적, 상대방(사라)의 국가·언어 입력
- 프로젝트에 쌓인 문서 목록이 뜹니다. 핵심 맥락 문서(`project-overview.md`)는 기본으로 포함되어 있고, 재현은 그 아래 목록에서 이번 회의와 관련 있어 보이는 파일들을 체크합니다: `schedule-agreement.md`, `sprint-notes-0728.md`. *(기능 1·2 — 회의 생성 시 파일 선택은 필수 단계)*

파일을 최소 1개는 선택해야 다음으로 넘어갈 수 있습니다 — 아무것도 안 고르고 회의를 만들 수는 없습니다.

선택한 파일들 안에서 AI가 예상 안건(질문)과 답변 초안을 만듭니다.

> **AI가 뽑은 예상 안건**: "API 마감일을 앞당길 수 있나요?"
> **AI 초안**: 선호안 "8/25 유지", 양보범위 "최대 8/28까지 가능" (근거: schedule-agreement.md)

이 안건은 일정 관련이라 AI가 선호안·양보범위 필드만 채웠습니다. 계약 관련 안건이었다면 양보불가사항까지 채웠을 것입니다. *(기능 2 — 안건 성격에 맞는 필드만 자동 판단)*

생성된 안건 목록을 보다가 재현은 "어, 최근에 올린 delay-reason-0810.md도 이 얘기랑 관련 있는데" 싶어서 근거 문서 목록에 추가합니다. AI는 조정된 범위로 안건을 다시 만듭니다. *(기능 1·2 — 생성 후에도 근거 문서 추가/제외 조정 가능)*

재현은 이 초안을 읽고 "이 정도면 맞네" 하고 그대로 승인만 누릅니다. 처음부터 다 타이핑할 필요 없이, 확인·승인만 한 것입니다.

이어서 재현은 AI가 뽑지 않은 안건 하나를 직접 추가합니다: "혹시 QA 인력도 추가로 필요할지 물어보면?" — 답변까지 직접 작성해 등록합니다. *(기능 3 — 사용자 직접 안건 추가)*

이런 식으로 예상되는 안건 몇 개를 승인하고 잠자리에 듭니다. *(기능 3 — 안건과 권한 범위 승인)*

## 새벽 2시, 사라 — 미팅 시작

사라가 미팅을 엽니다. AI가 먼저 음성으로 말합니다.

> "저는 재현님을 대신해 사전 승인된 범위 안에서 진행합니다. 범위를 벗어나는 사안은 보류 후 전달됩니다."

사라는 이게 사람이 아니라 대리 진행 AI라는 걸 명확히 인지한 채로 대화를 시작합니다. *(기능 5 — AI 대리 진행 고지)*

**사라**: "API 마감일 3일만 당길 수 있나요?"

AI는 이 발화를 실시간으로 텍스트로 바꾸고, 화자 분리도 됩니다 — 사라 발언과 AI 발언이 구분되어 기록됩니다. *(기능 4 — 실시간 음성 인식 및 화자 분리)*

재현이 승인해둔 안건 중 의도가 일치하는 걸 찾습니다. "양보범위: 최대 8/28까지 가능"이 이 질문과 맞아떨어집니다. 이 답변엔 날짜(숫자)가 포함되어 있어, AI는 답변과 함께 사라의 화면에 확인 팝업을 띄웁니다: `"8/28이 맞습니까? [O] [X]"`. 사라가 O를 누르자 AI가 영어로 통역해서 음성으로 답합니다: "8/28까지는 가능합니다." *(기능 6 — 승인 답변 통역 전달 + 숫자/단위 확인)*

**사라**: "그럼 계약 기간도 같이 늘려야 하나요?"

이건 재현이 사전에 승인해둔 안건에 없는 내용입니다. AI는 지어내지 않고 답합니다.

> "이 부분은 보류로 기록하고, 재현님께 확인 후 전달하겠습니다." *(기능 6 — 핵심 의도 불일치 시 보류)*

사라는 이 항목이 중요하다고 생각해서 "필수검토"로 지정해둡니다 — 나중에 재현이 반드시 확인해야 확정되는 항목으로 표시됩니다. *(기능 10 — 필수 검토 항목 관리)*

---

## 아침 9시, 재현 — 일어나서 확인

밤사이 회의가 진행됐습니다(미팅 상태는 "후속답변대기"로 아직 완전히 끝나지 않은 상태). 재현은 사후검토 화면에서 화자별 대화 전문과 연결된 음성 구간을 봅니다. *(기능 9 — 대화별 회의 결과 검토)*

- "8/28까지 가능" 답변 → 사라 반응이 "좋습니다"였던 걸 확인 → 승인
- 보류로 넘어간 "계약기간 연장" 질문 → 재현이 직접 판단해서 텍스트로 답변 작성 → 사라에게 **비동기로 전달** *(기능 8)*. 사라가 지정한 필수검토 항목("계약기간 연장")도 이 답변과 함께 처리되어 "조건부합의"에서 확정 대기 상태로 넘어갑니다 *(기능 10)*

---

## 그날 저녁, 사라 — 답변 확인

사라는 재현이 남긴 "계약기간 연장" 답변을 확인합니다. 사라는 이 정도면 충분하다고 생각해 별다른 반응을 하지 않습니다. 시스템은 별도로 "만족하셨나요?"를 묻지 않습니다 — 사라가 능동적으로 이의를 제기하지 않으면 그대로 확정됩니다. *(기능 8 — 기본은 1회 답변으로 종결, 확인 절차로 인한 핑퐁 방지)*

이 항목까지 종결되면서, 이 미팅에 남아있던 보류 항목이 모두 처리됩니다. 시스템은 자동으로 미팅 상태를 "종료"로 전환합니다 — 재현과 사라 둘 다 별도로 "종료" 버튼을 누를 필요가 없습니다.

> **만약 사라가 만족하지 못했다면?** 사라는 "re-open"을 눌러 다시 이의를 제기할 수 있습니다. 이 경우 재현이 다시 답하고, 같은 흐름이 반복됩니다. 다만 이 항목에 대한 재오픈은 최대 2회까지만 허용되고, 그래도 합의가 안 되면 시스템은 "이 사안은 비동기로 풀기 어려우니 실시간 미팅을 다시 잡으세요"라고 양쪽에 안내하고 이 항목을 종결시킵니다. 모든 이견을 이 서비스 안에서 무한정 흡수하려 하지 않는 것입니다.

## 이 스토리가 보여주는 것

| 순간 | 해결한 문제 |
|------|-------------|
| 재현이 프로젝트 개요 md를 핵심 맥락 문서로 먼저 올림 | AI가 프로젝트 전체 맥락을 먼저 잡아 이후 검색 정확도 향상 |
| 재현이 md/Notion 연동으로 문서를 책장처럼 계속 쌓아둠 | 회의마다 자료를 처음부터 올리지 않아도 됨 |
| 회의 생성 시 이름·목적만 입력하고 관련 파일 몇 개만 선택 | 입력 부담 최소화하면서도 AI 생성 범위를 사용자가 통제 |
| 생성 후에도 근거 문서를 추가/제외로 조정 가능 | AI 자동검색의 오류 가능성을 사용자가 조정할 여지 확보 |
| AI가 안건 성격 맞춰 필드만 채우고, 재현은 승인만 | 사용자가 처음부터 다 쓰지 않음 |
| 재현이 놓친 안건을 직접 추가 | AI 초안의 한계를 사용자가 보완 |
| AI가 "재현님을 대신함"을 명확히 고지 | 신뢰·투명성 확보 |
| 날짜(숫자) 답변에 확인 팝업 | 숫자 오인식 리스크 대응 (신뢰성) |
| 모르는 질문은 지어내지 않고 보류 | 권한 범위를 넘지 않는 AI (신뢰와 권한) |
| 사후검토에서 화자별 전문+음성으로 재현이 확인 | 책임 소재 보호, 사후 통제권 유지 |
| 사라가 반응 없으면 그대로 확정, 능동적으로만 재오픈 | 실시간 핑퐁을 비동기에서 재현하지 않음 |
| 재오픈 최대 2회, 그 이상은 실시간 미팅 권고 | 서비스가 모든 이견을 다 흡수하려 하지 않음 — 명확한 한계 설정 |
| 양측 종료 버튼 없이 보류 항목 종결 시 자동 종료 | 종료 확인 자체가 핑퐁이 되는 것 방지 |

**아직 이 스토리로 해결되지 않는 것**: 사라(질문 참여자) 입장에서 "이게 정말 재현이 아니라 AI라는 걸 알면서도 이 정도로 편하게 받아들일까"는 여전히 검증되지 않은 가설입니다. 데모 스토리는 이상적인 케이스를 보여주는 것이고, 실제 수용성은 별도 인터뷰로 확인이 필요합니다.
